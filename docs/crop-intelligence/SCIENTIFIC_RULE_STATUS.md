# Scientific rule status

**All 60 7V candidates remain blocked. Zero executable rules are accepted.**
The exact original review is retained at
`docs/integration/7v/SCIENTIFIC_REVIEW.md`; the original evidence matrix,
`blocked-rules.json`, schemas and input pins remain byte-identical to the base.

The interface exposes each candidate's block reason, contradictions and required
evidence. There is no approval endpoint or mutation of candidate metadata.
`recommendation_eligible` is always server-owned false in this workstream.

For each proposed future rule, an independent dossier must establish:

1. Original authoritative source or experiment.
2. Exact claim, page/table/row/footnotes and source locator.
3. Species, harvested crop type, cultivar and establishment/management method.
4. Region, climate, season and production system.
5. Compatible units, temporal statistics, depth and chemical/data methods.
6. Contradictions and uncertainty, without selecting a favorable value.
7. Field-applicability evidence and appropriate agronomist/field validation.
8. Independent reviewer role, date, decision, evidence and precise approval scope.

Rice water regimes, grain versus sweet maize, mung bean/Penauk identity,
sesame's inconsistent stage example and groundnut growth types remain distinct.
Annual rain is not seasonal demand; seasonal average temperature is not a daily
extreme threshold. Source pH without method/depth is not directly comparable to
a laboratory sample or SoilGrids layer. No Kc curve is approved by this package.

The UI's per-domain required-evidence lists are review preparation tools.
An agronomist must review a separately versioned applicability package before
any future executable threshold is integrated. Software tests and AI agreement
do not satisfy that review. No qualified human reviewer was supplied here.
