# Backend API v1 — proposal for review

This proposal is additive and does not approve or rename Rust/Flutter fields.
Only `server/` is changed. Existing Rust v0.1 `SeasonalRequest` and
`EnvironmentInput` field names are preserved. Rust v0.2 is not assumed.

`GET /api/v1/health` returns local service status and `upstream_checked: false`.

`GET /api/v1/environment/season` requires exactly six unique query parameters:
`latitude`, `longitude`, `start_year`, `start_month`, `end_year`, `end_month`.
Coordinates are finite WGS84 numeric degrees in [-90,90], [-180,180], preserved
without rounding; years start at 1981, months are 1–12. Endpoints are inclusive
full months, ordered, at most 24 months, ending before the current UTC month.
NASA publication lag can still make past months incomplete. Unknown/duplicate
parameters return 422 to expose client mistakes.

Successful shape (full example can be generated by the explicit live smoke):

```json
{
  "schema_version": "1.0-proposal",
  "status": "success",
  "environment": {
    "latitude": 16.85,
    "longitude": 96.15,
    "seasonal": {
      "window": {"start": {"year": 2024, "month": 2}, "end": {"year": 2024, "month": 2}},
      "metadata": {"source": "NASA POWER", "dataset": "POWER daily meteorology / MERRA-2", "data_kind": "modeled", "rainfall_unit": "mm", "temperature_unit": "deg_c"},
      "observations": [{"period": {"year": 2024, "month": 2}, "rainfall_mm": null, "mean_temperature_c": null, "rainfall_complete": false, "temperature_complete": false}]
    }
  },
  "provenance": {},
  "cache": {"hit": false, "ttl_seconds": 3600}
}
```

The null example is schematic, NOT downloaded data; production provenance is
populated, never `{}`. OpenAPI contains typed environment/seasonal models;
provenance/cache are extensible objects documented here:

- `provider`, `product`, `data_kind`, exact `query_coordinates`, inclusive ISO
  date `interval`, `time_standard`, original/normalized unit maps,
  `spatial_support`, `aggregation`, documentation URLs and limitations.
- `source_requests[]`: endpoint, exact query, UTC ISO `retrieved_at`, original
  NASA header (including source list, fill value/API version when supplied),
  parameter descriptions/units, source geometry and messages. Geometry is retained
  separately from the requested point, never substituted for it.
- `coverage[]`: ordered month, expected Gregorian day count, per-parameter lists
  of missing/invalid YYYYMMDD dates and explicit completeness reasoning.
- Cache hit/TTL; timestamps are retrieval times, not times of cached delivery.

Loss-aware adapters:

1. Send only `response.environment.seasonal` to `analyze_season_json`.
2. Or copy `response.environment` to current Rust `IntegrationRequest.environment`,
   keep the farmer-selected field coordinates exactly equal, use `supplied_data`,
   and separately supply farmer soil/history, crop references and scenarios. This
   endpoint cannot fabricate a complete agricultural integration request.
3. Persist/pass the entire backend envelope beside the Rust request/result, joined
   to the same field/query/window. Rust denies unknown fields; do not inject the
   sidecar into its structs or discard it after extraction. A durable evidence ID
   and integrity binding require owner agreement (see questions).

Errors have `status: "error"`, `error: {code,message,retryable}`, no partial data.
422 `INVALID_INPUT`; 502 `UPSTREAM_REJECTED`, `UPSTREAM_INVALID_RESPONSE`,
`UPSTREAM_UNITS_CHANGED`, `UPSTREAM_TIME_STANDARD_CHANGED`; 503
`UPSTREAM_UNAVAILABLE` after bounded transient retries. Raw upstream bodies/URLs
and validation inputs are not echoed. Missing daily observations are successful
incomplete evidence, not transport errors. Full-month values are null unless all
calendar days for that variable are valid; null never means zero.
